# FitClub — система управління фітнес-клубом

Курсова робота з дисципліни «Документування програмного забезпечення та шаблони проектування» (Проєкт 14).
Веб-застосунок автоматизує роботу фітнес-клубу: облік клієнтів і абонементів, реєстрацію відвідувань,
керування тренерами й розкладом, запис на заняття, автоматичні сповіщення та звіти.

## Основні функції
| Функція |
|---|
| Облік клієнтів: ПІБ, вік, телефон, абонемент, термін дії абонемента |
| Відстеження відвідувань: кожен прихід клієнта (check-in) реєструється в базі даних |
| Управління тренерами: профіль зі спеціалізацією, графіком роботи і списком клієнтів |
| Запис на групові тренування та індивідуальні заняття |
| Тарифні плани: разове відвідування, абонемент на місяць, на рік, на N відвідувань; додаткові опції |
| Автоматичне повідомлення клієнтів про закінчення терміну дії абонемента |

**Звіти:** активність відвідувань клієнтів, доходи клубу за місяць / рік,
завантаженість тренерів і залів по днях.

## Ролі користувачів
| Роль | Можливості |
|---|---|
| Гість | Перегляд тарифів, розкладу і тренерів, реєстрація |
| Клієнт | Купівля абонемента, запис на заняття та скасування, історія відвідувань, сповіщення |
| Тренер | Власний графік роботи, список своїх клієнтів і записів |
| Адміністратор рецепції | Реєстрація відвідувань, облік клієнтів, оформлення абонементів |
| Адміністратор клубу | Керування тренерами, залами, розкладом, тарифами й налаштуваннями; звіти |

## Технологічний стек
- **Backend:** Python 3.14, FastAPI, SQLAlchemy 2, Alembic, Pydantic v2, JWT, APScheduler
- **База даних:** PostgreSQL 16 (Docker Compose)
- **Frontend:** React (JavaScript, Vite), Ant Design, React Router, Axios, Recharts
- **Якість коду:** ruff, ESLint, Prettier

## Архітектура
Шарова архітектура бекенду: REST-роутери → сервіси → доменна модель → репозиторії → БД.
Бізнес-логіка побудована на GoF-шаблонах (Factory Method, State, Decorator, Strategy, Facade,
Chain of Responsibility, Command, Observer та інші), принципах SOLID і GRASP.

## Структура репозиторію
```
backend/
  app/
    api/            — REST-роутери (FastAPI)
    services/       — сервіси: сценарії використання
    domain/         — доменні моделі та шаблони проектування
    repositories/   — доступ до бази даних
    schemas/        — Pydantic-схеми (DTO) запитів і відповідей
    core/           — налаштування, підключення до БД
    main.py         — точка входу застосунку
  alembic/          — міграції бази даних
frontend/
  src/
    api/            — HTTP-клієнт (Axios) і запити до API
    pages/          — сторінки застосунку
    theme/          — тема Ant Design
diagrams/           — UML-діаграми (PNG)
seed/               — скрипт демо-даних
docker-compose.yml  — PostgreSQL
.env.example        — приклад змінних середовища
```

## Розгортання і запуск

### Вимоги
- [Python 3.14](https://www.python.org/downloads/)
- [Node.js 24](https://nodejs.org/) (разом із npm)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (для PostgreSQL)

### 1. Змінні середовища
Скопіюйте `.env.example` у `.env` у корені проєкту, змініть пароль бази даних (і в `POSTGRES_PASSWORD`,
і в `DATABASE_URL`) та задайте власний `JWT_SECRET` — випадковий рядок щонайменше з 32 символів:
```bash
cp .env.example .env
```
PostgreSQL з Docker доступний на порту `5433`, щоб не конфліктувати з локально встановленим PostgreSQL.

### 2. База даних
```bash
docker compose up -d
```

### 3. Backend
```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux / macOS: source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload
```
Команда `alembic upgrade head` створює таблиці бази даних і запис налаштувань клубу за замовчуванням.

Перед першим запуском створіть обліковий запис адміністратора (з каталогу `backend`):
```bash
python -m app.cli create-admin --email admin@example.com --password <пароль-від-8-символів>
```
Решту користувачів (рецепцію, тренерів, клієнтів) адміністратор додає через застосунок; клієнти можуть
також зареєструватися самостійно.
API доступне на http://localhost:8000, документація Swagger — http://localhost:8000/docs.
Разом із сервером запускається щоденна перевірка абонементів (час задається в налаштуваннях клубу,
`PATCH /api/settings`); її можна виконати й вручну: `POST /api/notifications/run-check`.
Без `SMTP_HOST` у `.env` листи не надсилаються, а записуються в лог сервера; SMS — завжди імітація.
Звіти доступні адміністратору в JSON, CSV і PDF: `GET /api/reports/{client-activity|income|load}?format=pdf`
(для PDF використано шрифт DejaVu Sans, `backend/app/assets/fonts`, ліцензія — `LICENSE-DejaVu.txt`).

Щоб викликати захищені ендпоінти у Swagger, виконайте `POST /api/auth/login`, скопіюйте `access_token`
і вставте його у вікні **Authorize**.

### 4. Frontend
```bash
cd frontend
npm install
npm run dev
```
Застосунок відкривається на http://localhost:5173. Запити до `/api` Vite перенаправляє на backend.

### Демо-дані (необов'язково)
Щоб наповнити базу прикладами (клієнти, тренери, тарифи, абонементи, відвідування й заняття за кілька
останніх тижнів), виконайте з кореня проєкту після `alembic upgrade head`:
```bash
python seed/seed_demo.py          # з активованим віртуальним середовищем backend
```
Скрипт очищає всі таблиці, крім налаштувань клубу, і заповнює їх заново; дати рахуються від поточного дня.
Демо-облікові записи: `admin@fitclub.example` / `admin123`, `reception@fitclub.example` / `reception123`,
`trainer1@fitclub.example` … `trainer4@fitclub.example` / `trainer123`,
`client1@fitclub.example` … `client25@fitclub.example` / `client123`.

### Перевірка якості коду
```bash
pip install -r backend/requirements-dev.txt
ruff check .                 # лінтер Python (з кореня проєкту)
cd frontend && npm run lint  # ESLint
```
